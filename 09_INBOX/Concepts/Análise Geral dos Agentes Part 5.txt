    • Filtro Econômico: Evitar operações durante eventos econômicos de alto impacto.

2. Detalhamento dos Componentes
2.1 Sistema de Logs e Gerenciamento de Erros
A classe ErrorHandler é responsável por registrar e notificar erros críticos.
Métodos Principais
    • LogError(int errorCode, string context):
        ◦ Registra mensagens de erro com código, contexto e horário.
        ◦ Notifica a equipe caso o erro seja de alta severidade.
    • HandleTradeError(int retCode):
        ◦ Trata códigos de erro retornados durante operações de trading.
        ◦ Exemplo: Invalidação de níveis de preço ou erros desconhecidos.

2.2 Filtro de Calendário Econômico
A classe EconomicFilter verifica se há eventos econômicos próximos que possam impactar as operações.
Funcionalidades
    • IsTradeAllowed():
        ◦ Itera pelos eventos econômicos armazenados.
        ◦ Bloqueia operações caso haja eventos de alto impacto dentro da janela temporal configurada (30 minutos).
Estrutura de Dados
    • NewsEvent Struct: Armazena informações sobre cada evento (horário, importância, moeda, descrição).

2.3 Análise de Padrões de Candlestick
A classe CandlePatternAnalyzer identifica padrões gráficos relevantes, como o "martelo".
Parâmetros Customizáveis
    • BODY_TO_WICK_RATIO: Relação entre corpo e mecha do candlestick.
    • MIN_CANDLE_SIZE: Tamanho mínimo do candlestick para validação.
Método Principal
    • IsHammerPattern(int shift):
        ◦ Calcula o tamanho do corpo, mecha superior e mecha inferior.
        ◦ Valida se o padrão atende aos critérios do martelo.

2.4 Implementação de Design Patterns
O projeto utiliza padrões de design para criar estratégias flexíveis e modularizar o código.
Strategy Pattern
    • A interface ITradeStrategy define métodos comuns para estratégias de entrada e saída.
    • A classe RSIStrategy implementa uma estratégia baseada no indicador RSI.
Factory Pattern
    • A classe StrategyFactory cria instâncias de estratégias com base no tipo especificado.
    • Facilita a adição de novas estratégias sem modificar o código existente.

2.5 Sistema de Logging Detalhado
A classe Logger registra todas as ações importantes do sistema, facilitando a análise posterior.
Níveis de Log
    • LOG_ERROR: Problemas críticos.
    • LOG_WARNING: Situações suspeitas ou anormais.
    • LOG_INFO: Informações gerais sobre operações realizadas.
    • LOG_DEBUG: Detalhes técnicos para depuração.
Métodos Principais
    • LogTradeAction(string action, MqlTradeRequest& request):
        ◦ Registra informações sobre ordens executadas (ação, símbolo, volume, preço).
    • LogSignal(string type, string reason):
        ◦ Registra sinais gerados pelo sistema (tipo, razão, horário).

2.6 Estrutura Principal Atualizada
A classe SamsungGlobalMarket integra todos os componentes mencionados acima.
Inicialização
    • Instancia objetos das classes:
        ◦ ErrorHandler: Para tratamento de erros.
        ◦ EconomicFilter: Para evitar operações arriscadas.
        ◦ CandlePatternAnalyzer: Para identificar padrões gráficos.
        ◦ ITradeStrategy: Para decidir entradas e saídas.
        ◦ Logger: Para registrar ações importantes.
Processamento em Tempo Real
    • OnTick():
        ◦ Verifica se operações são permitidas usando IsTradeAllowed() .
        ◦ Combina sinais de estratégia (ShouldEnterTrade ) e padrões de candlestick (IsHammerPattern ).
        ◦ Executa ordens quando condições forem satisfeitas.
