===============================================================================
OBJETIVO DO SISTEMA
===============================================================================

O ModuleRegistry é o CÉREBRO CENTRAL que mapeia e controla todas as 
dependências e integrações do EA Numeia, evitando o EFEITO CASCATA 
de atualizações não sincronizadas.

PROBLEMA RESOLVIDO:
- Antes: Mudanças em um módulo quebravam outros sem aviso
- Agora: Sistema detecta e previne quebras de dependências

===============================================================================
ARQUITETURA DO SISTEMA
===============================================================================

1. MODULE REGISTRY (Core/ModuleRegistry.mqh)
   ├── Registro automático de módulos
   ├── Mapeamento de dependências
   ├── Controle de integrações
   ├── Validação de integridade
   └── Análise de impacto

2. SCRIPT DE REGISTRO (Scripts/RegisterAllModules.mq5)
   ├── Registro automático de todos os módulos
   ├── Configuração de dependências
   ├── Estabelecimento de integrações
   └── Validação inicial

3. MONITOR EM TEMPO REAL (Scripts/DependencyMonitor.mq5)
   ├── Monitoramento contínuo
   ├── Detecção de mudanças
   ├── Análise automática de impacto
   └── Alertas em tempo real

4. PAINEL VISUAL (Include/Visuals/DependencyDashboard.mq5)
   ├── Interface gráfica
   ├── Status em tempo real
   ├── Visualização de dependências
   └── Estatísticas do sistema

===============================================================================
ESTRUTURA DE DADOS
===============================================================================

struct ModuleInfo {
   string moduleName;           // Nome do módulo
   string filePath;             // Caminho do arquivo
   string moduleType;           // Tipo (Core, Agent, Analysis, etc.)
   datetime lastModified;       // Última modificação
   bool isActive;               // Status ativo/inativo
   string version;              // Versão do módulo
   string description;          // Descrição funcional
};

struct DependencyInfo {
   string sourceModule;         // Módulo que depende
   string targetModule;         // Módulo dependido
   string dependencyType;       // Tipo de dependência
   bool isCritical;             // Dependência crítica
   string interface;            // Interface utilizada
};

struct IntegrationInfo {
   string moduleA;              // Primeiro módulo
   string moduleB;              // Segundo módulo
   string integrationType;      // Tipo de integração
   string dataFlow;             // Fluxo de dados
   bool bidirectional;          // Integração bidirecional
};

===============================================================================
EXEMPLOS DE USO
===============================================================================

1. REGISTRAR NOVO MÓDULO:
   ModuleRegistry* registry = GetModuleRegistry();
   registry.RegisterModule("NovoModulo", "../Include/NovoModulo.mqh", "Analysis", "Descrição");

2. REGISTRAR DEPENDÊNCIA:
   registry.RegisterDependency("ModuloA", "ModuloB", "include", true);

3. REGISTRAR INTEGRAÇÃO:
   registry.RegisterIntegration("ModuloA", "ModuloB", "execution", "data_flow", true);

4. ANALISAR IMPACTO:
   registry.AnalyzeImpact("CoreBrainManager");

5. VALIDAR INTEGRIDADE:
   bool ok = registry.ValidateIntegrity();

6. GERAR RELATÓRIO:
   registry.GenerateDependencyReport();

===============================================================================
TROUBLESHOOTING
===============================================================================

PROBLEMA: "Dependência quebrada detectada"
SOLUÇÃO: Verificar se o módulo alvo existe e está acessível

PROBLEMA: "Módulo órfão detectado"
SOLUÇÃO: Verificar se o módulo é realmente necessário ou adicionar dependências

PROBLEMA: "Dependências circulares detectadas"
SOLUÇÃO: Reestruturar dependências para evitar loops

PROBLEMA: "Mudanças não detectadas"
SOLUÇÃO: Verificar intervalo de scan e configurações de monitoramento
